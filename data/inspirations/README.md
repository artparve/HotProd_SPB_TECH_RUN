# Подготовленная подборка интерьеров

Production `manifest.json` содержит 32 реальные фотографии Pexels: по семь гостиных, спален, кухонь и ванных, по две детских и балкона. JPEG уменьшены до ширины 1440 px. Авторы, исходные страницы, лицензия, размеры и контрольные суммы перечислены в [CREDITS.md](CREDITS.md). Фотографии включены в backend Docker image, метаданные автоматически импортируются командой init-data; ключи и сеть для показа подборки не нужны. Галерея показана независимо от загрузки/распознавания плана и шага калькулятора.

## Как хранятся изображения

MongoDB, коллекция `inspiration`: `_id`, `id`, `title`, `category`, `description`, `alt`, относительный `file`, `sourceUrl`, `sha256`. Бинарные данные и Base64 в Mongo не сохраняются; GridFS не используется. Оригиналы — файлы в `data/inspirations/`, в контейнере обычно `/app/data/inspirations/`. Java отдаёт их через `/api/v1/room-inspirations/{id}/image`, проверяя SHA-256, а PNG-превью генерирует из оригинала через `/thumbnail`. Ссылка `sourceUrl` — атрибуция, не runtime-загрузка.

Дополнение из 12 фото описано в `additions.json`. Повторная подготовка файлов и manifest: `python -B scripts/fetch_inspirations.py`. Для явной загрузки отсутствующих файлов разрешите сеть: `python -B scripts/fetch_inspirations.py --download`. Это не Pinterest/Pexels API и не фоновый парсер: скачиваются только заранее выбранные фото с CDN Pexels. Скрипт не подключается к БД; после сборки нового backend image bootstrap импортирует manifest в Mongo.

На 31.10.2026 [официальный API Pinterest](https://developers.pinterest.com/docs/getting-started/connect-app/) требует business account, регистрацию и одобрение приложения, а затем токен. [Общий поиск чужих пинов](https://github.com/pinterest/pinterest-python-generated-api-client/blob/main/docs/SearchApi.md) доступен только части приложений в beta. Это не общедоступный источник изображений без регистрации. По запросу пользователя вместо него подключена локальная подборка по [Pexels License](https://www.pexels.com/license/), разрешающей использование фотографий в приложениях.

Чтобы расширить или заменить подборку, поместите сюда PNG/JPEG с разрешением на использование и внесите записи:

```json
[
  {
    "id": "living-01",
    "category": "living",
    "title": "Гостиная",
    "description": "Описание интерьера",
    "alt": "Доступное описание изображения",
    "file": "living-01.jpg",
    "sourceUrl": "https://www.pexels.com/photo/<photo-slug-and-id>/"
  }
]
```

Нужны сам локальный файл и HTTPS-ссылка на исходную страницу Pexels либо Pinterest (`pexels.com`, `www.pexels.com`, `pinterest.com`, `www.pinterest.com`, `pin.it`). URL с credentials, явно указанным портом или похожим чужим доменом отклоняется. Загрузчик ничего не скачивает. Добавьте автора в описание и обновите CREDITS.md; Pinterest-ссылка сама по себе не даёт прав на изображение. `id` стабилен, состоит из латинских букв, цифр, `_` и `-`, до 128 символов. Пустой `[]` остаётся допустимым для собственной установки.

До импорта проверяются дубли, путь (включая symlinks), формат, размер файла, pixel limit и метаданные. Затем весь набор метаданных заменяется одной транзакцией. Превью генерируется из локального оригинала. Изменение файла после импорта обнаруживается по SHA-256.

Для локального backend: `make backend-import-inspirations`. Для Docker добавьте файлы до сборки образа и повторите bootstrap, либо смонтируйте каталог read-only одновременно в backend и init-data и задайте INSPIRATIONS_DIR/INSPIRATIONS_MANIFEST. При смене образа перезапустите backend после импорта.

Модель предлагает тип покрытия и отделку стен. Java подбирает совместимые товары и проверяет полный комплект; цвет, фактура и точный товар по фото не подтверждаются. Размеры всегда берутся из формы. При отсутствии подходящего материала/сервиса исходный проект сохраняется.

Базовый Docker smoke проверяет все 32 production-фотографии, их байты, категории, cursor-пагинацию и превью, а также `unavailable` анализа без Python/Ollama. Браузер проверяет загрузку второй страницы и переключение категорий. `--runtime-only` поднимает официальный Ollama вместе с Python/Java/Mongo/frontend и проверяет деградацию при отсутствии установленной модели. Проверка с модельным транспортом копирует настоящую фотографию из подборки во временный каталог с отдельным тестовым ID; JPEG проходит Java → Python → модельный транспорт. Тестовая запись в production manifest не добавляется. Качество распознавания фотографий настоящей моделью требует отдельного LLM smoke.

`category` принимает `living`, `bedroom`, `kitchen`, `bathroom`, `children`, `balcony`, `other`. Старые записи без категории импортируются как `other`. Категория описывает фото и не меняет тип исходной комнаты. Встроенный набор проверяется в CI: по семь фотографий первых четырёх категорий и по две детских и балкона. При расширении набора обновите критерии тестов.

Для production-обновления используйте release-образ нового SHA: bootstrap существующей БД дополняет каталог отсутствующими учебными вариантами без перезаписи текущих товаров/правил, затем обновляет manifest изображений. Если применяете собственный read-only mount, его файлы должны быть доступны одинаково в `backend` и `init-data`; они заменяют встроенную подборку. Резервная копия Mongo содержит метаданные, поэтому сохраняйте также файлы подборки либо соответствующий release-образ.
