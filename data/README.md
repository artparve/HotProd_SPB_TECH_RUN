# Данные и заполнение MongoDB

## Первичная загрузка

1. Compose запускает MongoDB как одноузловой replica set. `docker/mongo/init.js` создаёт прикладного пользователя; это не загрузка товаров.
2. `init-data` выполняет `docker/init-data.sh`. Java импортирует `catalog-expanded.json` вместе с `work-mappings-expanded.json`, затем `rules-expanded.json`, затем `inspirations/manifest.json`.
3. Каталог сохраняется как immutable release: `catalog_release`, `product_revision`, `source_identity`, `source_record`. Правила сохраняются в `rule_set`; их точная ссылка на fingerprint каталога проверяется. Только после импорта правил активируется пара в `publication_pointer`.
4. Метаданные фото импортируются в коллекцию `inspiration`. Самих JPEG в MongoDB нет.

Повторный импорт той же версии с тем же содержимым — no-op; изменение содержимого под существующим номером версии запрещено. Java создаёт индексы. Python в MongoDB не пишет.

## Учебный каталог: 112 товаров

`catalog-expanded.json` содержит 12 исходных карточек с прежними ID и 100 новых. Новые варианты: гостиная, спальня, детская, кухня, ванная × скандинавский стиль, лофт, минимализм, неоклассика, джапанди × четыре материала. Среди них ламинат, кварцвинил, плитка, краска, обои, грунтовка и плиточный клей. Для влажных комнат используются совместимые учебные варианты плитки, краски, грунтовки и клея.

У каждого нового товара уникальные UUID/внешний ID, цена, описание, сопоставление работ и профиль Java. Комната и стиль также сохранены в raw-источнике. Стиль — описание товара, не новый фильтр совместимости и не гарантия точного совпадения с фото. Цены, нормы и свойства явно помечены **ТЕСТОВЫЕ**, это не реальные предложения магазина.

Исходные `catalog-v1.json`, `work-mappings-v1.json`, `rules-v1.json` сохранены неизменными для регрессионных проверок и воспроизводимости прежних релизов.

Воспроизвести расширенный набор без БД:

```sh
python -B scripts/generate_catalog.py
python -B -m unittest discover -s tests -p test_catalog_assets.py
```

## Существующая база и изменения администратора

CD с `docker-compose.preserve-data.yml` **не заменяет активный каталог/правила учебным seed**, поэтому существующие админские публикации сохраняются. При этом manifest галереи обновляется.

Новый каталог из 112 товаров автоматически используется на чистой установке. Для локальной БД, в которой допустима смена активной публикации, после backup:

```sh
make backend-import-catalog
make backend-import-rules
make backend-import-inspirations
```

Это не additive-merge: импорт новых правил переключает активную пару на расширенный учебный каталог. Не запускайте его поверх production с изменениями администратора без согласованного объединения данных. Код и данные в репозитории обновлены; удалённая БД этой задачей не изменялась.
