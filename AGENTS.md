# Работа с RepairCalc

- Начинай с `git status --short`; сохраняй чужие незакоммиченные изменения.
- Ищи адресно: `rg --files <каталог>`, затем `rg -n -m 20 '<символ>' <каталог>`;
  читай нужный диапазон через `sed -n '40,120p' <файл>`. Не читай весь репозиторий.
- `.ignore` убирает из общего поиска зависимости, сборки, отчёты и большие ресурсы.
  Если они нужны задаче, открой конкретный файл или используй
  `rg --no-ignore -n -m 20 '<символ>' reports/<нужный-каталог>`.
- Не загружай целиком каталоги JSON/XML, lock-файлы, логи и дампы. Для данных
  извлекай счётчики, выбранные поля и несколько примеров программно.
  Конфигурацию, манифесты и lock-файлы читай по необходимости задачи.
- Не читай локальные `.env` и секреты; используй примеры конфигурации.
- Логи ограничивай: `docker compose ... logs --no-color --tail 80 <сервис>`.
  Большой вывод проверок сохраняй в файл, показывай итог и релевантные ошибки;
  сохраняй и проверяй исходный код завершения команды.
- Выполняй проверки по затронутому компоненту. Не запускай модели, загрузки,
  весь Docker-стек или полный набор тестов только ради изучения проекта.
- Новый независимый запрос начинай в новом чате; при передаче работы оставляй
  кратко: цель, изменённые пути, проверки, оставшиеся шаги. Не сбрасывай активную задачу.

Карта: `frontend/src/` — Vue/TypeScript; `backend/src/` — Java/Spring и SQL-миграции;
`backend/data/` — учебные каталог/правила; `backend/estimation/` — Python estimator;
`backend/classification/` — классификатор, taxonomy и prompt; `docs/openapi.yaml` — API;
`docker/` и `docs/deploy.md` — запуск; `reports/` — исторические свидетельства по запросу.
Java определяет формулы, округление и стоимость; текст LLM не заменяет расчёт.

Проверки: frontend — `make check`; Java — `cd backend && ./mvnw test`
(интеграционные — `./mvnw verify`, нужен Docker); estimator —
`PYTHONPATH=backend/estimation python3 -m unittest discover -s backend/estimation/tests`.
Подробнее о контексте и ограничениях: `docs/AI_CONTEXT.md` (читай по необходимости).
