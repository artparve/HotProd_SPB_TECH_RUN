# Пользовательский вид подбора, 07.11.2026

Из результата убраны checksum, chunk ID, версии индекса/каталога и сырой текст извлечённых PDF. Технические данные остаются в API. На экране — карточки товаров с ценой за единицу продажи, блок стоимости и последовательные абзацы комментария модели. Источники свёрнуты и показывают только названия, страницы и ссылки. Ограничение применимости не скрывается: непроверенные SKU не разрешают расчёт. Финальные суммы возвращает Java.

Каталожные цены передаются из родительского экрана, а если каталог ещё не загружен — запрашиваются параллельно с подбором. Неизвестная цена не заменяется нулём. В каждой категории сначала четыре карточки, остальные доступны через «Показать ещё». Сетка адаптируется к доступной ширине, комментарии не используют глобальный flex-стиль alert.

Проверки в Docker: форматирование, TypeScript, 139 frontend-тестов, production build. После последней правки CSS и регрессии загрузки каталога повторно прошли 4 компонентных теста и production build. Регрессии проверяют отсутствие технических ID в DOM, цену при загрузке каталога, текстовую обработку ответа модели и блокировку неподтверждённых SKU.

Визуальная приёмка: preview http://127.0.0.1:5176/ с настоящим серверным API http://185.182.108.15/; запрос Quick-Step о поле с подогревом дал цены и настоящий комментарий Ollama. Проверены карточки/стоимость/комментарий в обычном браузере и карточки при ширине 390 px. Screenshot products.jpg, comment.jpg, mobile.jpg. Изменения сервера вручную не выполнялись.
