# Пересборка PDF-индекса при серверном деплое

Добавлен отдельный one-shot сервис `rag-index`, использующий LLM-образ релиза. Ansible запускает его на сервере после pull, до backup/перезапуска приложений. Готовый локальный индекс не передаётся. Каждый запуск заново извлекает все PDF и проверяет SHA-256. Успешный результат атомарно переключает `current`, предыдущие версии сохраняются. Ошибка сборки блокирует обновление приложений.

Проверки 07.11.2026:

- Собран актуальный `docker/llm.Dockerfile`.
- Два запуска реального контейнера `rag-index` без сети и модели: 19 PDF, 544 страницы, 2766 фрагментов; одинаковый хеш `35c7b11e474d061077ff9943e55a1687f9f49df501d1bcbf40fab46adaefb86d`.
- 3 unit-теста сборщика в Docker: контрольные суммы, страницы, идемпотентность, атомарное переключение и сохранение предыдущей версии.
- 18 тестов release-конфигурации в Docker: 14 passed, 4 skipped (нет Docker CLI внутри тестового контейнера).
- Реальная Ansible-роль с подставным Docker: успешный AI-релиз строит индекс до `up`; ошибка индекса сохраняет предыдущий `current` и не вызывает `up`/`stop`. 2 passed.
- Ansible syntax-check и Compose config с синтетическими паролями: passed.

Извлечение Poppler в новом контейнере отличается от ранее выполненной локальной CPU-пробы (2767 фрагментов). Контрольные суммы исходных PDF совпадают; хеш индекса учитывает фактически извлечённый текст. Повторяемость проверена внутри одного образа, версия `pdftotext` записывается в результат серверной сборки. Индекс остаётся `research_draft`, `usableForDecisions=false`, `productLinks=0`.
