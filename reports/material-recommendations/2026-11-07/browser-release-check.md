Через интерфейс «Подбор с источниками и ИИ-объяснением» проверены:

- Без опубликованной проверенной базы знаний кандидаты не подтверждаются, выбор/расчёт заблокирован. Это ожидаемая граница учебного каталога.
- Изменение работ сбрасывает устаревший результат.
- Quick-Step, напольное покрытие, обычная влажность/нагрузка, отопление/тёплый пол включены, справочные PDF и объяснение включены: RAG возвращает сообщение «Индекс справочных документов недоступен или не прошёл проверку». Реальный RAG inference в этом релизе не состоялся.

Диагностика на сервере была только для чтения. Backend настроен `RAG_REFERENCE_SEARCH_ENABLED=true`, `RAG_REFERENCE_INDEX=/app/reference-index/current`. Индекс 35c7b11e474d061077ff9943e55a1687f9f49df501d1bcbf40fab46adaefb86d создан сборщиком root с правами drwx------ (0700); Java UID 10001 не может прочитать этот каталог. Причина — режим TemporaryDirectory, сохранённый после rename.

Исправление: только для проверенных публичных артефактов индекса задаются 0755 на каталог и 0644 на corpus.json/manifest.json. Существующая версия получает эти права только после повторного извлечения PDF и полного сравнения контрольных сумм. CD перед успешным переключением релиза проверяет индекс запросом к Java API через frontend; unavailable или malformed ответ блокирует приёмку.

Проверки исправления: реальная сборка PDF в Docker; чтение обоих артефактов от UID 10001 с read-only mount и проверкой SHA-256 (index-java-uid-check.json); 3 unit-теста в Docker; 2 теста Ansible-ролей — успешная приёмка и отказ при недоступном индексе. Сервер вручную не изменялся. После CD исправления требуется повторить запрос с реальной Ollama в браузере.
