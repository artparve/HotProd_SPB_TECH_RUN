# Категории работ и поверхности: таксономия v2

Полный повторный разбор локальных датасетов выполнен 24 октября 2026 года. Таксономия — проект прикладных меток, выведенный из ассортимента и атрибутов; в исходниках нет готовой целевой разметки работ и поверхностей. Это не утверждение о качестве классификации.

## Источники и воспроизводимость

| Источник | Товаров | Используемых ID категорий | SHA-256 |
|---|---:|---:|---|
| products_final.json | 88,790 | 2,421 | `590a500be31d7a8d56e625c231ef978fc1a1a7b6d0a2e65eb33b88d68eee175e` |
| export_yandex_spb.xml | 61,406 | 2,268 | `886b804d3a8054b22938aa5b9d50e13152b16cb6fb59701a75f7ddf447df0fbf` |

XML содержит 3 326 категорий с иерархией; JSON — плоские ID и названия. Выгрузки пересекаются: количества и частоты между ними не суммируются. В этой работе каталоги анализируются независимо, без объединения товаров. JSON `id`, XML `offer/@id` и `cod_good` — разные идентификаторы. Повторяющиеся атрибуты сохраняются списком.

Частоты в taxonomy_support — широкие лексические совпадения, включая отрицания и неоднозначные смыслы. Для работ поиск идёт по категориям, для остальных осей — по всем текстовым полям. Например «пластик» часто является материалом корпуса, а не допустимым основанием. Эти числа служат для поиска примеров и формирования выборки, их нельзя использовать как готовые назначения, покрытие классификатора или оценку качества.

## Структура результата

| Ось | Смысл | Пример |
|---|---|---|
| work_types | Что делают | paint, electrical |
| surface_locations | Где применяют | floor, wall, ceiling |
| substrates | На какой материал наносят/монтируют | concrete, wood, metal |
| properties | Подтверждённые свойства и ограничения | moisture_resistant=yes/no/unknown/conflict |

Все три списка многометочные. Краска для стен и потолков: paint + wall + ceiling. Универсальность не означает все возможные метки. Для товаров вне ремонта используется scope=out_of_scope; недостаток данных или отсутствие подходящей категории — scope=uncertain и ручная проверка.

## Что нельзя смешивать

- Влагостойкость — отдельное свойство. Гидроизоляционные работы — waterproofing. Моющиеся обои не получают автоматически допуск в душевую.
- Влагостойкость есть как явно положительная, так и отрицательная: в JSON встречаются «да», «нет», а у обоев — «моющиеся», «влагостойкие», «супермоющиеся», «не влагостойкие». Нет атрибута — unknown.
- «Тип поверхности» перегружен: матовая/глянцевая/полированная — фактура; дерево/минеральная/металл — потенциальные основания. Важен смысл конкретной карточки.
- «Тип основы» с акриловой/алкидной/флизелиновой основой описывает товар. «Материал основания» встречается у мебели и ковров (джут, хлопок, ЛДСП) и также не всегда обозначает основание для нанесения.
- Напольный керамогранит может иметь floor и tile; краска для стен — paint и wall. Один атрибут не должен заменять всю классификацию.
- Фасады МДФ кухонной мебели, семена, посуда и щепа для копчения не должны попадать в строительные категории из-за совпадения слов.
- Материалы и инструменты получают виды работ по назначению, но свойства будущего покрытия не приписываются кистям/валикам.

## Связь с текущим backend

В Java work-taxonomy-v1 опубликованы только floor, paint, wallpaper, electrical. Новая прикладная таксономия имеет свою версию repair-product-taxonomy-v2 и автоматически в БД не импортируется. Совпадение ID не гарантирует совпадение определения: существующее paint ограничено окраской стен, новый paint шире. Для импорта нужны отдельный адаптер, проверка определения каждого назначения, новая версия каталога/маппинга и при расширении API — миграция контрактов. Вывод модели не является расчётным правилом и не содержит норм/цен.

## Проверка качества

Structured output ограничивает форму и допустимые ID. Pydantic проверяет согласованность состояний, списков и review-флага; код отдельно проверяет наличие каждой цитаты в указанном поле входа. Это не доказывает логическую достаточность цитаты: семантические ошибки всё ещё возможны.

Проверка реализации: 13 автоматических тестов, включая цепочку реальных компонентов LangChain/ChatOllama/Pydantic с заменённым транспортом Ollama. Первоначальная проверка выполнялась без загруженной модели. После загрузки пользователем проведены [7 реальных прогонов](live-2026-10-24/README.md): все выбранные проверки прошли, но ручной просмотр выявил смешение шпатлёвки и штукатурки. Добавлены таксономия/промпт v2; [отдельный повторный прогон](live-2026-10-24-putty-fix/README.md) прошёл все 7 проверок, включая точный список оснований. Независимые micro/macro-F1 не измерены. Для оценки нужна независимая ручная multi-label разметка по всем осям, отдельные примеры отрицаний/конфликтов/неремонтных товаров и разбиение по группам cod_good, чтобы один товар из разных выгрузок не попал в train и test. Считать micro-F1 и macro-F1 по видам работ и поверхностям отдельно, качество свойств — с unknown/conflict; дополнительно измерять долю ошибок API/схемы и долю ручной проверки.
