## Причина и восстановление production

- Активный релиз: `sha-f4c73472c46aef9a547b81dbf56171087a46d9da`, project `repaircalc_prod`, frontend `127.0.0.1:8081`.
- Работали frontend, backend и Mongo. LLM-сервис отсутствовал; backend ожидал `http://llm:8010`.
- Отдельный `repaircalc-ollama-1` был healthy в сети `repaircalc_default`. Модель `gemma4:12b` уже установлена, digest `6114515d63c17436a7c0417d82820ac65ad643e2806c5a3c89cb62846436ed0b`, volume `repaircalc_ollama-data`. Пустой `ollama ps` до запроса означает отсутствие загруженного runner, а не отсутствие модели на диске.
- В браузере до исправления Java вернула смету, а блок ИИ сообщил о недоступности пояснения.
- Существующая Ollama подключена также к `repaircalc_prod_default`. Загружен LLM image **того же релиза**, digest `sha256:b8aef446815fac04a31a69c832339462756a8602ebecf1a2f37acefa88e45f8f`.
- Запущен только `llm` через текущие release manifests с `--no-deps --no-build --pull never --wait`. База, backend и frontend не перезапускались; секреты не выводились.
- Оба контейнера имеют постоянную restart policy; восстановление использует старый контейнер Ollama и его volume. Это текущая runtime-конфигурация, а не новый полный CD.
- В текущий release установлен [docker-compose.recovery.yml](docker-compose.recovery.yml), задающий `OLLAMA_URL=http://repaircalc-ollama-1:11434`. LLM пересоздан только с этим override и дождался healthy. Временный alias `ollama` у старого контейнера убран: будущий project-local сервис сможет использовать собственное имя без конфликта. При ручном повторном `compose up` текущего release нужно включать recovery override; обычный Docker restart сохраняет адрес.

## Живая проверка

Браузер повторно отправил запрос с включённым ИИ: 20 м², 2 слоя, запас 10%. Получено пояснение `gemma4:12b`, объясняющее потребность 5,28 л, покупку 2 банок и остаток 4,72 л. Независимая проверка: `20 × 0.12 × 2 × 1.1 = 5.28`; `ceil(5.28 / 5) = 2`; `2 × 2490 = 4980` рублей.

`scripts/ensure_model.py --check-only` выполнен внутри production LLM-контейнера: `{"model":"gemma4:12b","status":"ready"}`. Повторного скачивания не было. Ollama показывает `100% GPU`, контекст 16384. Сервисы healthy; `/healthz` — `ok`. Последние ошибки/предупреждения консоли браузера: пустой список.

Свидетельства: [снимок пояснения](public-ai-result.jpg), [состояние сервера](server-state.txt), [консоль браузера](browser-console.json).

Не позднее 30 секунд после нажатия кнопки в браузере отображались модель `gemma4:12b` и пояснение: потребность **7,92 л**, **2 банки**, **4980 рублей**, остаток **2,08 л**. Проверка: `30 × 0.12 × 2 × 1.1 = 7.92`; `ceil(7.92 / 5) × 2490 = 4980`. [Финальный снимок](public-ai-result-30m2.jpg), [полный текст UI](final-browser-state.txt). Консоль после повторного запроса также без ошибок и предупреждений. Точное время завершения между опросами не измерялось; 30 секунд — верхняя граница наблюдения.

Остался ранее существовавший дефект оформления: модель повторяет служебный JSON перед читаемым пояснением. Числа в смете определяет Java; текст модели не является источником расчёта.

## Подготовленное исправление CD

В рабочей копии добавлены: включение ИИ по умолчанию в workflow, ранняя проверка служебного токена, опция `DEPLOY_OLLAMA_GPU`, скачивание отсутствующей локальной модели, проверка загрузки весов перед обновлением `current`. Внешняя Ollama проверяется без скачивания. Локальный ручной release по-прежнему требует явного `DEPLOY_LLM_ENABLED=true`.

На момент первичной проверки изменения оставались локальными; последующая отправка выполняется по отдельному запросу пользователя. Для следующего CD на этом NVIDIA-сервере нужны `DEPLOY_LLM_ENABLED=true` и `DEPLOY_OLLAMA_GPU=true` в GitHub Environment. Их значения через GitHub в этой проверке не менялись. Новый локальный `repaircalc_prod` Ollama по умолчанию получит собственный volume и скачает модель туда; старая копия сохранится. Старый alias `ollama` из `repaircalc_prod_default` уже убран.

Локальные проверки: 18 тестов release-конфигурации, 12 GitHub Actions, 6 протокольных тестов подготовки модели и 10 тестов Ansible-роли прошли (всего 46). В том числе проверено, что незагружаемая модель блокирует `current`, а GPU override включается для настроенного стенда. Лог Ansible: [ansible-tests.log](ansible-tests.log). `git diff --check` прошёл.
