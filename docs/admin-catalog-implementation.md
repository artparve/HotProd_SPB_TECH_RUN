# Административный каталог: CRUD и продолжение

30.10.2026. Реализована часть этапа 2 [спецификации](admin-catalog-spec.md): серверный доступ, ручные черновики, список и история. Продолжение: [классификация, проверка и публикация](admin-workflow.md). Ниже описана первоначальная поставка CRUD.

## Что работает

- `/admin`: вход/выход, список с поиском по названию или внешнему ID, точными фильтрами категории/статуса, сортировкой и страницами; новая карточка; форма полей/источников/характеристик; история снимков с автором, временем и request ID.
- `/api/v1/admin`: `GET /session`, `POST /login`, `POST /logout`, `GET/POST /products`, `GET/PUT /products/{id}`, `GET /products/{id}/history`. [OpenAPI](openapi.yaml) ссылается на [отдельный административный контракт](admin-catalog-api.json). Административный клиент всегда обращается к серверу через same-origin `/api/v1/admin`, независимо от `VITE_DATA_MODE`.
- V5: карточки с постоянной внешней идентичностью, неизменяемые версии, неизменяемый аудит. Ссылка на первую версию проверяется при commit; версия обязана принадлежать карточке. Предыдущие миграции не менялись.
- API отклоняет неизвестные поля, повторные JSON-ключи, дополнительные корневые значения, неверные типы/единицы, неположительные цену/фасовку/расход/размеры и отрицательный раппорт. Максимальный размер JSON — 256 КиБ, до 200 источников и характеристик. Деньги — строка до 17 цифр до точки и двух после, валюта — RUB. Поддерживаемые единицы перечислены в контракте.
- Обязательны `sourceNamespace`, `externalId`, `name`. Проверяемые поля имеют `{state,value,source,confirmedBy}`; отсутствие поля означает `unset`. `unknown` и `unset` не содержат ненулевого значения, `confirmed` требует значения и источника. Автор подтверждения всех `confirmed`-полей при сохранении берётся из сессии. Присланный `confirmedBy` не даёт возможности подменить автора. Непроверенные булевы значения не преобразуются в `false`.
- Изменение под блокировкой строки проверяет `If-Match`, добавляет версию, переводит рабочую карточку в `draft` и записывает аудит одной транзакцией. HTTP `ETag` — UUID версии в двойных кавычках. Без `If-Match` — 428; несовпадение — 412; смена внешней идентичности — 409. Форма при 412 оставляет введённые поля и предлагает явно перечитать карточку.
- Дубликат идентичности возвращает 409 с `details[{field:"id",code:"existing_product",message:"UUID"}]`. Для идентичности из старого каталога используется исходный UUID. CLI-импорт проверяет также административные идентичности и не может перепривязать их другому UUID. Создание сериализовано общим с CLI advisory lock.
- Черновик и его изменения не меняют активный публичный release. GET карточки возвращает рабочую версию. Публикация и её точные version/review/release/rules UUID сохраняются отдельно в V7; см. продолжение.

## Доступ и запуск

Один именованный администратор получает полномочия из серверной конфигурации; публичный API остаётся анонимным. Без обеих настроек `ADMIN_USERNAME` и `ADMIN_PASSWORD_HASH` все административные маршруты возвращают 503 `admin_disabled`. Перед вводом пароля frontend получает анонимную сессию и CSRF-токен; вход заменяет сессию и токен. Все изменяющие запросы, включая вход/выход, требуют `X-CSRF-Token`.

Из корня репозитория выполните:

```bash
python3 backend/scripts/admin-password-hash.py
```

Скрипт читает пароль дважды без эха и выдаёт строку `ADMIN_PASSWORD_HASH='...'`. Используется PBKDF2-HMAC-SHA256, 600000 итераций и случайная соль 24 байта. Пароль не передаётся аргументом процесса и не записывается в файл. Поместите выданную строку с одинарными кавычками в локальный `env/.env`; кавычки сохраняют буквальные `$` в Compose. Задайте `ADMIN_USERNAME`. В `VITE_*` пароль или хеш помещать нельзя.

Cookie имеет `HttpOnly`, `SameSite=Strict`, путь `/api/v1/admin`, имя `REPAIRCALC_ADMIN` и по умолчанию `Secure`. Для локального HTTP-стенда, доступного только через loopback, явно задайте `ADMIN_COOKIE_SECURE=false`; для HTTPS используйте `true`. `ADMIN_SESSION_SECONDS` задаёт абсолютное время жизни и предел неактивности (по умолчанию 1800 секунд, разрешено 60–86400). Сессии находятся в памяти процесса: перезапуск требует повторного входа. Не включать несколько backend-реплик без общего хранилища сессий/лимитера.

На один адрес разрешено пять попыток входа в минуту, на процесс — 30. При превышении возвращаются 429 и `Retry-After: 60`; лимитер использует непосредственный адрес соединения, за reverse proxy лимит может быть общим для его пользователей. Учётные данные и CSRF не пишутся в журнал. Ошибки содержат безопасные `code`, `message`, `requestId`, `details`; ответы имеют `Cache-Control: no-store`.

Существующие proxy Vite/nginx маршрутизируют `/api/` в Java; новый отдельный upstream не требуется. Compose передаёт настройки только backend/init-data. Пересоберите backend и frontend обычной командой проекта и откройте `/admin`. Для прямого запуска Java переменные из `backend/.env.example` нужно экспортировать в процесс: Spring сам файл `.env` не загружает.

Пример тела создания: [admin-product-draft.example.json](../backend/data/admin-product-draft.example.json). Это одиночный административный снимок, не файл для CLI `import-catalog` и не будущий пакетный импорт.

## Проверки и оставшиеся этапы

Проверки и точные команды текущего изменения сохраняются в [отчёте](../reports/admin-catalog/2026-10-30/README.md). PostgreSQL API IT проверяет реальные HTTP-сессии и CSRF, конфликт версий, одновременное изменение, историю, фильтры, ограничения JSON и rollback при ошибке аудита. Отдельно проверяются сохранение публичного UUID и изоляция черновика от публичного snapshot. Frontend проверяет контракт OpenAPI/Zod и сохранение формы при 412.

Классификация, проверка, вычисляемая готовность и атомарная публикация добавлены в [продолжении](admin-workflow.md). Остаются архивирование, очередь внимания, preview/пакетный импорт, расширенные фильтры и серверные рекомендации. Свежие проверки и ограничения перечислены в [новом отчёте](../reports/admin-workflow/2026-10-30/README.md).
