# ADR 002: Java, MongoDB replica set и внутренний Python LLM

Решение принято по утверждённому плану. Оно заменяет PostgreSQL/JPA/JDBC/Flyway и прямой SQL-worker из ADR 001.

Публичные маршруты, бизнес-арифметика, версии каталога/правил, административный процесс и durable queue принадлежат Java. Mongo хранит отдельные коллекции, суммы Decimal128 и даты BSON Date. Published content изменяется созданием новых ревизий. Один publication_pointer атомарно выбирает каталог и rule set; транзакция включает статус и аудит. Seed повторяем и не возвращает указатель к старым данным.

MongoDB запускается в Docker как одиночный replica set с аутентификацией и постоянным volume. Replica set нужен для multi-document transactions ([MongoDB docs](https://www.mongodb.com/docs/manual/core/transactions/)); он не обеспечивает HA с одним узлом. Импорт PostgreSQL-истории отложен, старые volumes сохраняются.

Python выполняет только inference/валидацию схем: классификация, план, интерьер, объяснение уже рассчитанной сметы. Внутренний HTTP требует токен; все операции делят один semaphore. Никаких DB writes и самостоятельной публикации. Ollama может быть внутренней или внешней; загрузка модели — явное действие оператора.

При сбое чтения возвращается типизированный пустой результат с причиной. Расчёт/запись при недоступной БД завершаются ошибкой. Сбой LLM не удаляет Java-смету и не меняет введённую комнату.

Подборка Pinterest подготовленная и локальная; URL — атрибуция, не инструкция скачать произвольный ресурс. До предоставления файлов manifest пуст. Изображение не определяет геометрию, нормы, цены и точный SKU.

Проверка решения: Java unit/Mongo integration tests, Python tests, production frontend build и scripts/verify-stack.py с реальными сервисами и заменой только транспорта модели.
