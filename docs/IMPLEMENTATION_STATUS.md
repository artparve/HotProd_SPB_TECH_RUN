## Реализовано

- Java владеет MongoDB, опубликованной парой каталог/правила, административными версиями, аудитом и очередью.
- Три Java-калькулятора, комплекты материалов, совместимость, смена покрытия и проверка selections.
- Python HTTP-сервис классификации, планов, интерьеров и объяснений с общей очередью допуска к модели.
- Подготовленная лента интерьеров Pexels/Pinterest, выдача файлов, анализ по ID и контролируемые пустые результаты.
- Корневые `data`, `llm`, `docker`, `scripts`, `env`, обновлённые API/Zod и фолбеки frontend.
- CI и release gate `main`, три образа, перенос Ansible в `docker/ansible`.
- Переопределяемые env-пути данных и промптов, типизированные лимиты, раздельная передача секретов.
- Проверяемые backup/restore Mongo в новую БД с SHA-256 и сравнением количества документов.
- При замене технологии frontend получает допустимые альтернативы от Java и пересчитывает зависимости выбранного материала.

- `make check`: форматирование, TypeScript, 109 unit-тестов и production-сборка frontend.
- Playwright: 14 demo-сценариев и 22 сценария с API-моками на desktop/mobile.
- 32 теста estimator, 24 классификатора, 7 нового Python gateway.
- 7 тестов общего конфигуратора, 8 smoke-протокола и 67 release/runtime-тестов после исправления CI. Восемь Ansible-тестов, пропускаемые на Windows, отдельно успешно выполнены в Linux-контейнере с настоящим Ansible 2.19.4 и имитацией Docker CLI.
- Настоящие Java/Mongo/Python/nginx в изолированном Compose: 3 браузерных сценария, каталог, рекомендации, расчёты, планы, изображения и пояснение. Подменён только транспорт Ollama.

- Backup и восстановление архива в отдельную новую БД, рестарт с сохранением опубликованных данных.
- Отдельная остановка Ollama, Python, Mongo и Java: API возвращают предусмотренные фолбеки или 503, обычная смета не зависит от модели.
- Базовый Compose запускается без Python, Ollama и сервисного токена; все 20 production-фотографий и превью выдаются из backend image.

## Оставшиеся внешние входы и границы

- Реальный inference не выполнялся: `127.0.0.1:11434` недоступен. Транспортная имитация не считается проверкой качества модели. Тег контейнера Ollama доступен в registry; модель автоматически не скачивалась.
- Production manifest содержит 20 реальных фотографий интерьеров Pexels (по пять гостиных, спален, кухонь и ванных), включённые в backend image. Исходные страницы, авторы, лицензия и SHA-256 — `data/inspirations/CREDITS.md`. Официальный Pinterest API требует одобрения приложения и токена; вместо публичного поиска используется локальная подборка. Базовый Docker smoke проверяет её импорт/файлы/превью и деградацию анализа без модели; качество настоящего inference остаётся отдельным этапом.
- Данные, нормы и цены учебные. Коммерческий импорт, остатки/заказ, RAG, автоматическое принятие меток и независимый ML-бенчмарк остаются следующим этапом.
- Обученная корректирующая модель не настроена: `useCorrection=true` явно возвращает 422. Offline-обучение сохранено; обычные Java-расчёты и LLM-пояснение работают без коррекции.
- Ручное размещение на внешнем сервере и ручная публикация образов в этой сессии не выполнялись. Push запускает CI; успешность удалённых image/CD workflows этим локальным отчётом не подтверждается. Ansible проверен локально; фактический CD запускается оператором.

Пользовательские локальные env не изменялись. Старые PostgreSQL volumes не затрагивались. Удалялись только volumes созданных проверками проектов `repaircalc_verify_*`.

При переключении с `main` исходный untracked `.idea/vcs.xml` сохранён в `.idea/vcs.xml.main-untracked.bak`; отслеживаемый файл ветки `backend` не перезаписывался пользовательской копией.

Особенности среды проверки: стандартный Maven Central отвечал 403, поэтому использовано публичное Google-зеркало. Один холодный старт официального Mongo 8.0 на Docker Desktop/WSL завершился `Address already in use` при смене временного процесса bootstrap; следующий запуск изолированного стека прошёл. При повторении такого сбоя следует сохранить ограниченные логи и повторить `up`, сохраняя рабочий volume.

## Расширение галереи и проверок запуска, 31.10.2026

20 JPEG (3 420 876 байт) хранятся в Git и backend image: пять гостиных, пять спален, пять кухонь и пять ванных. Категории проходят через Mongo/API/Zod и доступны как фильтры в галерее. Режим обновления существующей БД импортирует новый manifest без повторного импорта учебных каталога/правил; сквозной тест предварительно очищает галерею и проверяет её восстановление с сохранением опубликованных товаров.

В CI проверяются три режима Compose: полный сценарий с подменой транспорта модели, базовый стек с 20 фотографиями и браузерным выбором категорий, полный профиль с официальным Ollama и пустым модельным volume. Модель не скачивается; отсутствие модели даёт `unavailable`, качество настоящего inference проверяется отдельно. Это проверка контейнерной поставки, а не свидетельство запуска CD на внешнем стенде.
