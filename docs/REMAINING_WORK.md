## 3. Эксплуатационные ограничения

- Mongo работает одиночным replica set: транзакции есть, высокой доступности нет. Многоузловой production-кластер не развёрнут.
- Backup/restore реализованы и проверены. Архив Mongo не включает файлы изображений: после наполнения галереи нужно сохранять assets/manifest либо соответствующий immutable image и проверять их совместное восстановление. Автоматический DR и переключение на восстановленную БД не выполняются.
- Предрелизный backup кратко останавливает прежний Java writer и возобновляет его в `finally`. Это предусмотренное окно недоступности записи, а не online backup без остановки.
- Admin использует HTTP-сессию приложения и одного настроенного оператора. После рестарта требуется вход заново; распределённые сессии и управление несколькими администраторами не реализованы. Код: [AdminAuth.java](../backend/src/main/java/ru/repaircalc/admin/AdminAuth.java).
- На Docker Desktop/WSL один холодный bootstrap официального Mongo 8.0 завершался `Address already in use` при смене временного процесса. Повторные полные прогоны прошли. Перед production полезно закрепить проверенный image digest и проверить воспроизводимость старта; рабочий volume при таком сбое удалять нельзя.

## 4. Что уже работает и не является заглушкой

- Три калькулятора выполняются в Java по настоящим Mongo snapshots; упаковки, деньги, комплекты и тарифы не подменяются ответами модели.
- Версии карточек, ETag/CSRF, классификационная очередь с арендой, human review, атомарная публикация и аудит сохраняются в Mongo.
- Python действительно обрабатывает переданные карточки/изображения/снимок расчёта через внутренний HTTP API. Отсутствие реального model smoke отмечено выше отдельно.
- Пустая лента и типизированные ответы `unavailable/no_matches` — предусмотренная деградация. Ошибки расчёта/записи остаются явными; недоступная модель не стирает настоящую смету.
- `frontend/src/services/demo.ts`, демонстрационная лента и `llm/tests/fake_ollama.py` остаются для разработки/тестов. Production не переключается на них при сбое.
- `main`-изменения deploy не оставлены PostgreSQL-заглушками: preflight, принятие существующего Mongo project, backup, фиксация volume и закрытая диагностика адаптированы и проверены.
