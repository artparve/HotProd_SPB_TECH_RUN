# Отдельный тест Gemma 4 12B через Ollama

## Что предусмотрено в текущем бэкенде

Проверено по исходникам ветки `backend` 24.10.2026:

- Java 21 / Spring Boot обслуживает каталог и расчёт одного товара. Вызов `POST /api/v1/product/{id}/calc` проходит через `ProductCalculationController` → `ProductCalculationService` → `MaterialCalculator`.
- Расчёт детерминированный; `ProductCalculationService` явно возвращает `versions.model = "not-used"`. Модель не вызывается ни при расчёте, ни при импорте каталога/правил.
- В `backend/pom.xml` нет модельного SDK; в `application*.yml` и `.env.example` нет параметров LLM/Ollama. В Java-исходниках нет клиента inference или запуска модельного процесса.
- `docker/docker-compose.yml` запускает только frontend, без Ollama и Java backend.
- Локальная LLM есть в планируемой архитектуре корневого README. Её подключение к Java API ещё не реализовано.

`scripts/ollama_smoke.py` — независимый ручной smoke test. Он обращается напрямую к отдельному серверу Ollama, скачивает модель при `--pull` и выполняет текстовый inference через `/api/chat`. Java, PostgreSQL, frontend и Python-пакеты ему не нужны. Сам процесс Ollama запускается отдельно.

## Модель

Исходная модель: [google/gemma-4-12B](https://huggingface.co/google/gemma-4-12B).
Для Ollama используется опубликованный тег [gemma4:12b](https://ollama.com/library/gemma4:12b), а не Hugging Face URL. Это распространяемая Ollama сборка модели; она может использовать квантизацию и отличается от исходных Safetensors. Тег может обновляться; `--json` сохраняет имя модели и ответ, но не фиксирует digest весов.

Нужна актуальная версия Ollama, поддерживающая этот тег, место для весов и достаточно RAM/VRAM для загрузки и контекста. Объём загрузки и текущие варианты сборки смотрите в карточке Ollama; фактическая потребность в памяти зависит от сборки, оборудования и `--num-ctx`. Скрипт проверяет только текстовый режим, без изображений/аудио.

## Запуск

Установите Ollama с [официального сайта](https://ollama.com/download). Python — 3.10 или новее, только стандартная библиотека.

В первом терминале, если Ollama ещё не запущена как приложение/служба:

```bash
ollama serve
```

Во втором терминале из корня репозитория:

```bash
# Первый запуск: скачивание весов, загрузка в память и тестовый ответ.
python3 scripts/ollama_smoke.py --pull

# Повторный запуск с собственным запросом.
python3 scripts/ollama_smoke.py --prompt "Перечисли три этапа подготовки стены к покраске."

# Полный ответ API со счётчиками токенов и длительностями.
python3 scripts/ollama_smoke.py --json > /tmp/gemma4-response.json
```

На Windows из корня репозитория: `py -3 scripts/ollama_smoke.py --pull`.

Веса также можно загрузить заранее командой `ollama pull gemma4:12b`, после чего запускать скрипт без `--pull`. Скачивание требует интернета на машине с Ollama; повторный inference уже загруженной локальной модели не требует Hugging Face токена или облачного API-ключа.

Для отдельно работающего сервера Ollama:

```bash
python3 scripts/ollama_smoke.py --host http://SERVER:11434 --timeout 1200
```

`SERVER` замените адресом доступного сервера. Настройка доступа к серверу выполняется отдельно. По умолчанию скрипт использует только `http://127.0.0.1:11434`; переменные Java backend ему не передаются.

## Результат и ошибки

Ответ модели печатается в stdout; прогресс загрузки и `OK: model=..., elapsed=..., generated_tokens=...` — в stderr. Exit code 0 означает завершённый непустой ответ. Exit code 1 означает ошибку подключения, загрузки, API, JSON, пустой или обрезанный ответ; 2 — неверные аргументы; 130 — прерывание пользователем.

При `--pull` для каждого слоя выводятся полный digest, полоса прогресса, процент, скачанный/полный объём, средняя скорость и ETA. Обновления ограничены одним в секунду на слой; завершение выводится сразу. Скорость вычисляется по приросту после первого наблюдения слоя: ранее скачанные байты не считаются новым трафиком. Первая строка и полностью кешированные слои показывают `measuring/cached`. ETA — оценка для отдельного слоя, а не всей модели. Общая сводка учитывает только слои, объявленные сервером. API сообщает слои (blobs), но не прогресс внутренних параллельных сетевых сегментов. Если сервер пропустил последнее событие счётчика слоя, финальный `success` подтверждает его готовность строкой `ready (pull success)` и 100%.

Весами управляет **сервер Ollama**. Файлы слоёв находятся в `<models>/blobs/sha256-<digest>`, манифесты — в `<models>/manifests/`. Каталог не передаётся в Pull API. Скрипт пробует прочитать настройку `snap get ollama models` для локального сервера; это подсказка конфигурации Snap, а не доказательство того, что именно этот процесс обслуживает порт. Если каталог неизвестен, скрипт сообщает об этом явно. Для удалённого сервера локальные настройки не используются.

На этой машине служба `snap.ollama.listener.service` использует `/var/snap/ollama/common/models` — подтверждено конфигурацией запущенного сервера 24.10.2026. Запуск с явным отображением проверенного пути:

```bash
python3 scripts/ollama_smoke.py --pull --models-dir /var/snap/ollama/common/models
```

`--models-dir` только выводит путь, **не меняет место скачивания**. Чтобы выбрать другое хранилище, требуется настроить сам сервер (`OLLAMA_MODELS` или соответствующая настройка установленного пакета); см. [Ollama FAQ](https://docs.ollama.com/faq#where-are-models-stored).

Здесь `snap get ollama models` от обычного пользователя возвращает `access denied`, поэтому автоматическое чтение настройки недоступно. Подтверждённый путь взят из startup-лога действующей службы; используйте показанный выше `--models-dir` для его отображения без дополнительных прав.

Для сохранения прогресса в файл на Linux/macOS:

```bash
python3 scripts/ollama_smoke.py --pull 2> /tmp/gemma4-download.log
# В другом терминале:
tail -f /tmp/gemma4-download.log
```

- Connection refused: запустите Ollama и проверьте адрес/порт.
- HTTP 404: проверьте тег, используйте `--pull`; сервер должен предоставлять Ollama API.
- Ошибка поддержки модели: обновите Ollama и повторите загрузку.
- Недостаточно памяти: освободите RAM/VRAM, проверьте `ollama ps`, при необходимости уменьшите `--num-ctx` (по умолчанию 4096).
- Долгая первая загрузка: увеличьте `--timeout` (по умолчанию 600 секунд на ожидание сетевой операции; это не общий лимит времени скачивания).
- Обрезанный ответ: увеличьте `--num-predict` (по умолчанию 512). Thinking отключён через `think=false`, модель остаётся загруженной до пяти минут (`keep_alive=5m`). Для ручной выгрузки: `ollama stop gemma4:12b`.

Это проверка доступности и генерации, а не оценка правильности рекомендаций, нормативов расхода или качества ML. Подключение к расчётам Java потребует отдельного клиента и контракта.

Протокол: [Ollama Chat API](https://docs.ollama.com/api/chat), [Pull API](https://docs.ollama.com/api/pull).

## Что проверено при добавлении

24.10.2026: проверены CLI `--help`, формирование запросов pull/chat, передача русского текста, вывод JSON, обработка 11 сценариев ошибок API/транспорта и пяти случаев неверных аргументов. Протокольные проверки выполнены с подставными ответами через `unittest.mock`, без настоящих весов.

При первоначальной проверке Ollama отсутствовала, порт возвращал connection refused. После установки пользователем подтверждена работа Snap Ollama 0.40.2 на `127.0.0.1:11434`; в логах обнаружен только CPU. Повторный запуск `--pull` подтвердил реальный поток прогресса и возобновление ранее начатой загрузки.

Реальный запуск завершился успешно: скачаны семь слоёв `gemma4:12b`, суммарно около 7,5 GiB с учётом ранее кешированных данных. Наблюдаемая скорость основной загрузки — около 10–11 MiB/s; она менялась по ходу скачивания. Текстовый inference с `think=false`, `num_ctx=4096`, `num_predict=128` завершился exit 0 за 24,49 секунды (включая загрузку модели в память), 25 выходных токенов. Это один замер, не benchmark.

После вызова `ollama list` показывает `gemma4:12b`, ID `6114515d63c1`, размер 8,0 GB; `ollama ps` подтверждает `100% CPU`, контекст 4096, runner `llamacpp`.

Запрос: «Ответь одним коротким предложением на русском: для чего нужна грунтовка стен?» Ответ: «Грунтовка нужна для улучшения адгезии отделочных материалов и уменьшения расхода краски или клея.»

Добавлены восемь воспроизводимых проверок прогресса по независимым слоям, ограничения частоты вывода, кеша, расчёта скорости после возобновления, подтверждения пропущенного 100%, удалённого пути, pull/chat и ошибок. Все восемь проходят. Запуск без Ollama и скачивания весов:

```bash
python3 -m unittest discover -s backend/scripts -p 'test_ollama_smoke.py' -v
```
