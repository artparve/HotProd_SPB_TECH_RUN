# Контракт frontend ↔ RepairCalc

Основной контракт теперь описан в **[openapi.yaml](openapi.yaml)** (OpenAPI 3.0.3). Файл можно открыть в Swagger Editor, подключить к Swagger UI или использовать для генерации клиента. Структура и ссылки проверяются автоматически вместе с frontend-тестами.

Это **предложение для будущего backend**, а не утверждение о существующем API. Внешний Bagisto API из DOCX требует отдельной нормализации. Backend, импорт каталога, ML и admin API здесь не реализованы.

## Маршруты

Базовый URL: `/api/v1`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/products` | Ограниченная нормализованная витрина товаров для виджета |
| POST | `/estimate` | Материалы и отдельно ориентировочные работы |
| POST | `/recommendations` | Товары под условия комнаты с объяснением |
| POST | `/product/{id}/calc` | Расчёт одного товара без стоимости работ |

Точные поля, обязательность, ограничения, nullable-значения, ответы и ошибки находятся в OpenAPI, а не дублируются в этом файле. `frontend/src/domain/types.ts` содержит соответствующие Zod-схемы runtime-проверки. Клиент пока написан вручную; генерация из OpenAPI не подключена.

## Важные договорённости

- Денежные суммы — десятичные строки в RUB. Цена относится к **единице продажи**, не к произвольной площади или массе.
- `quantity` в строке сметы — целое число единиц продажи. `need`, `purchased` и `remainder` выражены в `product.unit`.
- Для обоев `unit` — полотна, а единица продажи — рулон. Backend учитывает длину полотна, раппорт и подрезку.
- Условия влажности, нагрузки и отопления передаются явно. Неизвестная совместимость не означает разрешённую.
- `selections` связывает ключ `roomId:productKind` с `productId`; backend повторно проверяет выбор, цену и доступность.
- Геометрия требует серверной проверки: проёмы меньше площади стен; обои и краска не отделывают одновременно всю одну поверхность.
- Нельзя выдумывать расход или брать среднее диапазона без условий. Недостаток данных — повод вернуть 422 с запросом уточнения.
- `ApiError` в OpenAPI — предложенная схема для согласования. Сейчас UI показывает HTTP-статус, а не использует поля тела ошибки.

## Подключение

Настройки находятся в **`env/.env`**, создаваемом из `env/.env.example` командой `make init-config`:

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=/api/v1
API_UPSTREAM=http://127.0.0.1:8000
DOCKER_API_UPSTREAM=http://host.docker.internal:8000
```

`API_UPSTREAM` — backend для локального Vite; `DOCKER_API_UPSTREAM` — backend с точки зрения контейнера nginx. Браузер обращается к тому же origin через `/api/v1`. После изменения настроек перезапустите Vite или пересоберите Docker-сервис.

Таймаут — 15 секунд, `credentials: same-origin`. Ошибка сети, JSON, HTTP или схемы **не включает деморежим**. Авторизация, CSRF и production CORS требуют отдельного согласования; секретов в `VITE_*` быть не должно.
