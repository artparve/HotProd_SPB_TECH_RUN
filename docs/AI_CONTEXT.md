# Экономное чтение репозитория агентами

`AGENTS.md` содержит краткие инструкции и карту компонентов. Codex читает такие
инструкции при запуске: [официальная документация](https://learn.chatgpt.com/docs/agent-configuration/agents-md).
Этот документ предназначен для чтения по необходимости, а не для включения
целиком в каждый запрос.

## Что настроено

| Механизм | Действие | Ограничение |
| --- | --- | --- |
| `AGENTS.md` | Адресный поиск, небольшие диапазоны, ограниченные логи, карта кода | Инструкции агенту, не запрет доступа |
| `.ignore` | Исключения для обычного `rg`/`rg --files`, включая отслеживаемые отчёты и lock-файлы | Явный путь, `--no-ignore` и другие инструменты могут обходить правила |
| `.dockerignore` | Убирает мусор из контекста сборки от корня | Не ограничивает чтение файлов агентом и bind mounts |
| Компонентные `.dockerignore` | Фильтруют реальные контексты Compose | Корневой файл к этим контекстам не применяется |

Java и оба Python-сервиса используют списки разрешённых файлов. Для frontend
сохранены исходники, манифесты, lock-файл, Vite/TypeScript-конфигурация и nginx.
SQL-миграции в `backend/src/main/resources/db/migration/`, учебные данные в
`backend/data/`, схемы, тесты и `prompt.txt`/`taxonomy.json` остаются доступны
агенту. Lock-файлы скрыты только из общего поиска, но доступны явно и нужны сборке.
Локальные выгрузки, отчёты и runtime Ollama сохранены на диске.

Универсальная поддержка `.aiignore` не предполагается: здесь применяются
`AGENTS.md` и реально используемый `rg` файл `.ignore`. Для другого клиента нужно
проверить его поддержку инструкций и исключений. Ignore-файлы не защищают секреты
и не уменьшают уже накопленную историю чата.

## Примеры адресной работы

```bash
rg --files frontend/src/services
rg -n -m 20 'calculate|estimate' frontend/src/services backend/estimation/repaircalc_estimator
sed -n '1,100p' frontend/src/services/api.ts
# Отчёты читаются только когда нужны исторические свидетельства:
rg --no-ignore -n -m 10 'PASS|FAIL' reports/integration/2026-10-24/README.md
# Ключи npm scripts без чтения полного манифеста:
node -p 'JSON.stringify(require("./frontend/package.json").scripts, null, 2)'
```

Для диагностики Docker используйте команду Compose из `Makefile` с
`logs --no-color --tail 80 <сервис>`; при необходимости добавьте `--since 10m`.
Не используйте `--follow` для разовой проверки. Длинный вывод тестов сохраняйте
в файл, проверяйте код завершения и читайте нужный фрагмент, например:

```bash
make check > /tmp/repaircalc-check.log 2>&1
check_status=$?
tail -n 60 /tmp/repaircalc-check.log
test "$check_status" -eq 0
```

После завершения задачи новый независимый запрос удобно начинать в новом чате.
Для продолжения передайте цель, изменённые пути, результаты проверок и оставшиеся
шаги; не копируйте длинные логи и всю предыдущую переписку.

Headroom/RTK и другие прокси не установлены: базовая настройка обходится без
новых зависимостей и изменения сетевого пути запросов. Карта кода находится в
`AGENTS.md`; автоматического семантического индекса здесь нет. Процент экономии
токенов не измерялся и не гарантируется.

## Проверка настройки — 30 октября 2026

В текущей рабочей копии `rg --files --hidden -g '!.git/**'` до настройки
показывал 505 файлов, после — 238. Исключены из общего поиска 270 файлов отчётов
и `package-lock.json` (около 7,1 MiB суммарно); это объём файлов, не число токенов.
Проверены доступность исходников, фикстур, промптов, схем и всех SQL-миграций,
а также адресное чтение отчёта с `--no-ignore`.

Реальные правила Docker проверены через временный Dockerfile `FROM scratch` /
`COPY . /context/` с локальным экспортом результата для корня и четырёх
компонентов Compose. Во всех пяти контекстах нужные входные файлы сохранены,
проверенные кэши и лишние каталоги исключены. Для Java дополнительно сверены все
имена SQL-миграций. Приложения и модели не запускались; production-сборка этим
не проверялась. `git diff --check` прошёл.
