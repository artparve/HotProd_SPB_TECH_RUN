# Что изучено и что реализовано

## Все доступные материалы

| Материал | Вывод для frontend |
| --- | --- |
| `tech_description_of_task.md` | Три обязательных пользовательских сценария: общая смета, специфика комнаты, расчёт в карточке. |
| `answers_and_links.md` | Прозрачные коэффициенты, реалистичный тестовый каталог допустим. ML — многометочная задача, но frontend не обучает модель и не заявляет F1. Существующие пользовательские изменения этого файла сохранены. |
| DOCX кейса | Виджет Vue, размеры, стоимость материалов и работ, округление упаковок, локальный контур, API. Примеры API иллюстративные. Не нужно реализовывать backend, CV или ML на стороне браузера. |
| `Драфт решения.png` | Потоки frontend → API → калькулятор/подбор. `/design` из ранней схемы заменён `/recommendations` из плана. Админка и база не входят в запрошенную frontend-часть. |
| `README.md` | Идентификаторы товаров не взаимозаменяемы; цены, происхождение норм, версии и ограничения нужно показывать явно. До договора с магазином экспортируется JSON, а не оформляется заказ. |
| `PLAN.md` | Мастер, альтернативы с пересчётом, объяснения, состояния уточнения, три сценария. Бизнес-вычисления реального сервиса должны остаться в backend. |
| `INVENTORY.md` | Каталоги и видео хранятся отдельно. Для самостоятельного frontend достаточно обозначенных фикстур. |
| `reports/json_audit.md` | Нет изображений, актуальных остатков и готовых расчётных норм. Поэтому нет выдуманных фото, актуального наличия или реальных SKU: визуализации материалов сделаны CSS. |
| `reports/xml_audit.md` | Нужны единицы, проверка расхода, совместимости и фасовки; неизвестное не приравнивается к разрешённому. |
| `reports/video_audit.md` | Отчёт прочитан полностью. MP4 в текущей папке отсутствует, аудио не расшифровывалось; вопросы из видеочата не приняты за ответы. |
| `.gitignore` | Исключения крупных файлов сохранены, добавлены локальные настройки и результаты сборки. |

DOCX извлечён и прочитан целиком, PNG просмотрен. В текущей папке нет `products_final.json`, `export_yandex_spb.xml` и MP4; использованы их отчёты, без заявления о повторном анализе отсутствующих исходников. Внешние ресурсы не скачивались: для frontend они не нужны.

## Матрица интерфейса

| Требование | Реализация |
| --- | --- |
| Дом / квартира / студия, класс ремонта | `/`, первый шаг; контекст передаётся API. В демо класс не создаёт скрытую наценку. |
| Несколько помещений | Добавление/удаление, размеры и работы для каждой комнаты, максимум 20. |
| Пол, стены, обои, электрика | Независимые выбранные работы; обои и краска взаимоисключающие для одной полной поверхности стен. Для смешанной отделки — отдельные комнаты/зоны. |
| Размеры | Длина, ширина, высота, площадь проёмов; проверка проёмов относительно стен. |
| Влажность, нагрузка, отопление | Тип комнаты задаёт изменяемые начальные значения, `/room` показывает причины подбора. |
| Карточка товара | `/product?id=…`, параметры поверхности, слоя, раппорта или точек/трасс в зависимости от категории. |
| Запас и фасовка | Настраиваемый запас 0–30%, целые упаковки, потребность, купленное количество и остаток. |
| Прозрачность | Формула каждой строки, стоимость упаковки, версия каталога/правил/модели, ограничения. |
| Альтернативы | Выбор совместимого товара на шаге материалов с повторным запросом сметы. |
| Смета и корзина | Раздельные материалы/работы, сохранение до 30 смет в localStorage, JSON сметы и состава корзины. |
| Ошибки | Неверный ввод, пустой каталог/подбор, неподтверждённая норма, HTTP/сеть/таймаут, некорректная схема API, хранилище недоступно. |
| Закрытый контур | Нет внешних шрифтов, CDN, аналитики и удалённых изображений; после сборки демо автономно. |

## Что намеренно не реализовано

- Backend, импорт больших каталогов, база данных, ML, LLM/RAG, мини-админка.
- Авторизация, платёж, заказ, реальное наличие и региональные цены.
- Заявления о качестве ML или полной технологической комплектности сметы.
- Подготовка моделей и GPU-инфраструктуры: это выходит за frontend + Docker.

Учебные вычисления из `frontend/src/services/demo.ts` нужны только для автономного UX-прототипа. В `api`-режиме браузер получает расчёт от backend, не подменяет ошибку демоответом и не загружает демодвижок.
